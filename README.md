# 모아 — 커뮤니티 레이더

원하는 키워드로 커뮤니티·블로그·카페·SNS의 공개 검색 결과를 한곳에서 보는 웹입니다. PR Agent의 18개 소스에서 언론을 제외한 17개에 **X·Threads를 더한 19개**를 대상으로 검색합니다. 유튜브도 포함됩니다.

## GitHub Pages + Vercel 배포판

사이트: https://uhdh.github.io/moa-radar/

사이트 검색창에 키워드를 입력하거나 **키워드 추가**를 누르면 Vercel API가 등록하고 **바로 첫 수집**을 진행합니다. 완료되면 결과를 표시하며, 이후 GitHub Actions가 한국시간 매일 오전 9시부터 하루 한 번 갱신합니다. PC를 켜둘 필요가 없습니다. 예약 실행은 GitHub 상황에 따라 지연·누락될 수 있으며, 공개 저장소에서 60일 동안 활동이 없으면 예약이 비활성화될 수 있습니다.

- 첫 수집은 소스의 응답을 기다립니다. 완료 전에는 수집 중 상태를 표시합니다.
- 등록된 키워드 클릭·새로고침·정확한 단어 체크 변경은 오늘의 수집을 반복하지 않습니다.
- 첫 수집도 한국시간 기준 오늘의 1회에 포함됩니다. 실패·중단도 당일에는 재시도하지 않으며 이전 결과가 있으면 보존합니다.
- PostgreSQL의 원자적 수집 시작 기록을 네트워크 요청 전에 저장하므로 동시 요청·Vercel 재배포·다른 브라우저에서 같은 단어 등록·삭제 후 재등록으로 제한을 우회하지 않습니다.
- 키워드 목록·제외 단어·정확한 단어 설정은 DB에 저장하고 **현재 브라우저의 임의 접근 키**로 구분합니다. 다른 브라우저의 목록을 수정할 수 없습니다. 계정 로그인과 기기 간 목록 동기화는 없습니다. 사이트 저장소를 지우면 목록 접근 키도 사라집니다.
- 글 저장은 현재 브라우저에 보관합니다. 등록 키워드와 수집 결과를 GitHub 저장소에 커밋하지 않습니다. 동일한 키워드의 공개 게시글 수집 결과는 서버에서 재사용합니다.

배포 구성은 GitHub Pages(화면), Vercel Python Functions(API), Neon Free PostgreSQL(등록 목록·수집 기록), GitHub Actions(하루 1회 예약)입니다. [Actions 상태](https://github.com/uhdh/moa-radar/actions/workflows/pages.yml)에서 예약 실행을 확인합니다. GitHub 파일 편집 없이 사이트에서 등록·삭제할 수 있습니다.

무료 개인용 프로토타입의 한도는 브라우저당 30개, 서비스 전체 서로 다른 수집어 30개입니다. 새 등록은 IP당 하루 30개, 전체 하루 100개로 제한합니다. 이미 등록한 결과 읽기는 이 등록 한도를 사용하지 않습니다. 다중 사용자 서비스로 확장할 때는 이 한도와 계정 인증을 함께 변경해야 합니다.

운영 설정:

- Vercel의 `DATABASE_URL`은 Neon 연동으로 주입합니다. 새 DB는 `python cloud.py`로 테이블을 초기화합니다.
- Vercel `CRON_SECRET`과 GitHub Actions secret `MOA_CRON_SECRET`은 같은 임의 비밀값입니다. 브라우저나 저장소에는 넣지 않습니다.
- GitHub variable `MOA_API_URL`은 `https://moa-radar-api.vercel.app`입니다.
- `cloud_collect.py`가 인증된 예약 API를 호출합니다. 읽기 API는 수집을 시작하지 않습니다.
- DB를 연결한 검증: `python check_cloud.py` (`DATABASE_URL`, `CRON_SECRET` 필요). 고유 테스트 행만 만들고 제거합니다.

`keywords.json`·`state/collections.json`은 이전 정적 배포용이며 현재 클라우드 등록 목록으로 사용하지 않습니다. 로컬 `data/radar.sqlite3`와 브라우저 접근 키는 저장소·배포 묶음에 포함하지 않습니다. 아래 실행·사용 설명은 별도 Python 로컬 서버판 기준입니다.

근거: [GitHub Pages 워크플로](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages), [예약 실행 제약](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule).

## 실행

Windows에서 `start.cmd`를 실행하세요. Python 3.10 이상이 필요하며, Beautiful Soup이 없으면 설치합니다. 서버 실행 중에는 터미널을 열어두세요.

직접 실행하려면:

```powershell
python -m pip install -r requirements.txt
python server.py --open
```

주소: http://127.0.0.1:8787

다른 포트: `python server.py --port 8788 --open`

## 사용

- 검색창에 키워드를 입력합니다. 처음에는 `스팀`을 검색합니다.
- 검색창 아래 `정확한 단어만`을 체크하면 제목·요약에서 단어 단위로 일치하는 결과만 보여줍니다. 해제하면 기존 검색 범위로 돌아갑니다.
- 왼쪽에서 관심 키워드와 제외 단어를 저장하고, 19개 소스의 결과를 골라봅니다. 전체 선택·해제를 지원합니다.
- 관심 키워드는 **등록 후 처음 수집하고, 이후 한국시간 매일 오전 9시부터 하루 한 번** 수집합니다. 결과 위에 최근 수집 시각과 다음 일정을 표시합니다.
- 피드 위의 `SNS 바로보기`에서 X·Threads·유튜브 결과로 바로 이동합니다.
- 결과 검색·기간·정렬을 조합하고, 글을 저장하거나 원문을 엽니다.
- `저장한 글`은 검색어를 바꿔도 유지됩니다. CSV에는 현재 화면의 필터에 맞는 글이 들어갑니다.
- 관심 키워드·제외 단어·최근 수집 결과는 서버에 저장됩니다. 이 서버를 쓰는 브라우저들이 같은 관심 키워드 목록을 공유합니다. 개인 계정 구분은 없습니다.
- 저장한 글은 현재 브라우저에 보관됩니다. 기존 버전의 관심 키워드는 처음 접속할 때 서버로 옮깁니다.

## 정확한 단어만

체크하면 `스팀`, `스팀 할인`, `#스팀`, `(스팀)`은 일치하고 `스팀덱`, `슈퍼스팀`, `스팀2`, `스팀은`은 제외합니다. **붙은 조사도 다른 단어로 처리**합니다. 여러 단어를 넣으면 입력한 문구의 순서를 그대로 찾으며, 대소문자와 연속된 공백 차이는 무시합니다. 제목과 요약을 각각 검사하므로 제목 끝과 요약 앞의 단어를 합쳐서 문구로 인정하지 않습니다. 원문 본문에만 있고 제목·요약에 없는 단어는 이 모드에서 확인하지 못합니다.

설정은 관심 키워드별로 서버에 저장되고, 키워드 추가 창에서도 지정할 수 있습니다. 체크를 바꾸면 이미 가져온 결과만 다시 걸러서 글 목록·통계·CSV에 함께 적용합니다. 하루 수집 기록을 초기화하거나 추가 수집하지 않습니다. 저장한 글 보기에는 현재 검색어의 정확 일치 조건을 적용하지 않습니다.

## 하루 한 번 수집

저장한 관심 키워드를 클릭하거나 새로고침하면 **저장된 결과만 읽습니다**. 같은 날 추가 수집하지 않습니다. 제외 단어 수정, 서버 재시작, 키워드 삭제 후 재등록도 오늘의 수집 횟수를 초기화하지 않습니다. 관심 키워드를 삭제하면 다음 자동 수집에서 제외됩니다. 저장하지 않은 키워드의 일반 검색은 기존처럼 즉시 검색합니다.

수집 제한은 한국시간의 달력 날짜를 기준으로 하며, 새 키워드의 첫 수집도 그날의 1회에 포함됩니다. 예약 시각은 오전 9시이며 서버가 최대 1분 간격으로 확인하고 키워드를 순차 처리합니다. 처음 등록한 키워드는 대기열에서 바로 수집합니다. 모든 소스가 실패하거나 수집 중 서버가 종료돼도 그날은 재시도하지 않습니다. 이전 결과가 있으면 유지하고 다음 일정에 다시 시도합니다. 일부 소스 실패는 각 소스의 상태에 표시됩니다.

브라우저를 닫아도 **서버가 실행 중이면** 수집합니다. PC·서버가 꺼져 있던 날의 과거 결과를 소급해서 만들지는 않습니다. 오전 9시 이후 서버를 다시 켜면 아직 수집하지 않은 오늘 분을 수집합니다. 오전 9시 전이면 예약 시각을 기다립니다.

데이터는 기본적으로 `data/radar.sqlite3`에 보관합니다. 마지막 수집 결과를 키워드별로 저장하며, 날짜별 과거 결과를 계속 쌓는 방식은 아닙니다. 서버를 옮길 때는 서버를 종료한 뒤 이 파일을 함께 옮기세요. 파일을 지우면 수집 횟수 기록도 사라집니다.

배포 시에는 영구 저장소를 연결하고 경로를 지정해야 재배포 후에도 기록이 유지됩니다. 예를 들어 마운트 경로가 `/data`라면:

```sh
python server.py --host 0.0.0.0 --port "$PORT" --data-dir /data
```

현재 예약 수집은 서버 프로세스 하나를 기준으로 합니다. 서버가 잠자거나 꺼지면 예약 시각에 수집할 수 없으므로, 배포할 때 실행 환경의 스케줄·저장소를 함께 설정해야 합니다. 알림을 발송하지는 않습니다.

| X | Yahoo 공개 실시간 검색에 노출된 게시글 |
| Threads | Yahoo 공개 웹 검색, threads.com·threads.net 게시글 통합 |
| 인스타그램 | 공개 웹 검색; 로그인 전용 글·계정 소개 제외 |
| 페이스북 | 공개 웹 검색; 로그인 전용 글·계정 소개 제외 |

각 소스의 첫 결과 페이지에서 최대 25건을 가져옵니다. 검색과 통계는 전체 게시글 수가 아닌 **가져온 표본**을 기준으로 합니다. 검색어의 일치 방식은 각 사이트 검색을 따릅니다. 언론 사이트의 원문은 결과에 포함하지 않습니다.

직접 검색 실패 시 네이버 공개 웹 검색으로 보완합니다. X·Threads는 Yahoo의 공개 검색을 사용합니다. **공개 웹 검색** 배지를 표시하며, 색인 지연과 누락이 있습니다. 프로필·홈페이지·검색 페이지는 글로 집계하지 않습니다. 인스타·페북은 현재 확인 가능한 공개 게시글이 없어 제한 상태로 표시됩니다. 계정 로그인이나 차단 우회는 사용하지 않습니다.

X는 공개 실시간 검색의 첫 페이지, Threads는 신·구 도메인 검색의 첫 페이지를 합쳐 최대 25건입니다. Twitter 주소는 X 주소로 통일하고, Threads의 중복 주소·미디어 하위 주소를 하나의 글로 합칩니다. X·Threads도 제목·요약에 입력한 키워드가 있는 결과만 남깁니다. 전체 게시글이나 전체 과거 기록을 검색하는 범위는 아닙니다.

유튜브는 관련 없는 추천 영상을 제외하기 위해 제목·설명의 키워드 일치를 확인합니다. 동영상 자막이나 본문에만 있는 키워드는 찾지 못할 수 있습니다. 공개 웹 검색의 표시 날짜를 실제 게시일로 간주하지 않습니다.

최신순은 가져온 결과의 **게시 시각** 기준입니다. `몇 시간 전`, `어제`, X의 일본어 날짜, 시각만 있는 엠팍 글, 블라인드의 작성시간도 각 소스의 수집 시각에 맞춰 해석합니다. 추정해서 해석한 날짜에는 `추정`을 표시하고 원문 시간과 수집 기준 시각은 날짜의 도움말에 남깁니다. 상대시간은 페이지를 열 때의 현재 시각으로 다시 계산하지 않으므로 저장 결과·저장한 글의 날짜가 새로고침할 때 달라지지 않습니다. 수집 기준 시각이 없는 구버전 저장 글은 상대시간을 임의로 추정하지 않습니다.

날짜만 제공하는 글은 한국시간 해당 날짜를 기준으로 정렬하고, 같은 날의 시각이 있는 글 다음에 표시합니다. 지난 연도의 글은 연도도 표시합니다. 게시일을 알 수 없는 글은 최신순 목록 맨 아래에 별도 구분하며 기간 통계에서 제외합니다. 최근 24시간 집계에는 확인·추정 시각이 있는 글을 포함하고 날짜만 있는 글은 제외합니다. 댓글순에서 댓글 수가 같으면 같은 날짜 기준으로 최신 글부터 정렬합니다. CSV의 추정 시간에도 원문과 수집 기준 시각을 함께 씁니다.

저장하지 않은 키워드의 일반 검색은 키워드·소스별로 성공 결과 5분, 실패 결과 1분 동안 메모리에 캐시합니다. 이 임시 캐시는 서버 종료 시 사라집니다. 관심 키워드의 하루 1회 수집 기록과 결과는 SQLite에 별도로 보관해 서버 종료 후에도 유지합니다.

사이트가 접근을 제한하거나 검색 페이지 구조가 바뀌면 연결 상태에 표시합니다. 다른 커뮤니티의 결과는 계속 볼 수 있고, 연결 상태의 커뮤니티 이름을 누르면 원래 검색 페이지가 열립니다.

## 검증

```powershell
python check.py
python check_daily.py
python check.py --live
node --check public/app.js
node check_dates.mjs
node check_keyword.mjs
```

`check.py`는 19개 소스 등록, X·Threads 수집·중복 제거, 날짜 정밀도, 주소 식별 쿼리, 네이티브 파서 12개, 공개 웹 파서, 프로필 제외, 무관한 유튜브 추천 제외, 접근 제한, 반복 캐시 검색을 검사합니다. `--live`는 외부 사이트에도 실제 요청하므로 사이트 상태에 따라 결과가 달라집니다.

`check_daily.py`는 임시 DB로 최초 수집, 한국시간 오전 9시, 동시에 실행된 작업의 중복 방지, 새로고침·재시작·삭제 후 재등록, 전체 소스 실패·작업 중단, 키워드 API 검증을 검사합니다. 실제 다음 날까지 기다린 검사는 아니며 시계를 지정해 날짜 전환을 재현합니다.

`check_dates.mjs`는 외부 요청 없이 여러 소스의 날짜 혼합 정렬, 한국시간 날짜 처리, 상대시간, X 날짜, 월·연도 전환, 날짜 미확인과 저장 글의 기준 시각 유지를 검사합니다.

`check_keyword.mjs`는 한글 단어 경계, 붙은 조사·합성어 제외, 해시태그·문장부호, 구문 순서, 정규식 특수문자, 강조 위치를 검사합니다. 브라우저에서도 체크·해제, 키워드별 설정 유지, 통계·CSV, 저장 실패 복구, 빈 결과와 모바일 표시를 확인했습니다.

하루 1회 기능은 실제 브라우저에서도 기존 키워드 이전·첫 수집·저장 결과 새로고침·다른 브라우저 접속·제외 단어 수정·삭제 후 재등록·모바일 표시를 확인했습니다. 이 과정에서 저장된 결과와 수집 시각이 그대로 유지됐습니다.
